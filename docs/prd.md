# RadiVault — Product Requirements Document (PRD)

> **Status**: Draft v0.1 · **Last updated**: 2026-04-22
> 이 문서는 RadiVault 플랫폼 전체의 제품 요구사항을 정의합니다. 세부 기능별 dev-spec은 `docs/specs/dev-spec-*.md`에서 개별로 작성합니다.
> **근거 문서**: [docs/research/k-meddata-research-summary.md](research/k-meddata-research-summary.md)

## 1. 비전

한국 의료기관의 의료영상(DICOM) 데이터를 **완전 익명화 상태**로 수집·인덱싱하여 글로벌 AI 기업·제약사·연구기관이 **합법적으로 구매**할 수 있는 B2B 데이터 브로커 플랫폼.

**한 줄 요약**: "Korea's medical imaging data, compliantly delivered to the world's AI."

## 2. 타깃 사용자

### Primary (구매자)
- **AI/의료기기 기업** — 모델 학습·검증, FDA/CE 인허가용 데이터셋 필요.
- **제약/바이오 기업** — 임상시험 환자 모집, 약물 반응 예측.
- **학계/연구기관** — 출판용 데이터셋, 임상 연구.

### Secondary (공급자)
- **한국 의료기관** — 상급종합병원·종합병원·전문병원. PACS 보유 필수.
- **병원 내 의사결정자** — 영상의학과장, 임상연구지원실, 정보보호책임자.

### Internal (운영자)
- RadiVault 운영팀 — 데이터 QA, 라벨링 관리, 판매·계약 관리.

## 3. 핵심 가치 제안

| 사용자 | 가치 |
|--------|------|
| AI 기업 | 한국 다양성 데이터 + 빠른 조달(48시간 내) + 인허가 레퍼런스 데이터 |
| 병원 | 데이터 수익화 + 게이트웨이 무상 제공 + 데이터 주권 유지 (원본은 병원에 잔존) |
| 환자 | 완전 익명화로 사생활 보호, 의료 AI 발전 간접 기여 |
| 규제당국 | 투명한 익명화 이력 + 감사 로그 + 국외이전 규제 준수 |

## 4. 제품 범위 — 기능 요구사항

### 4.1 병원 Gateway Agent (Phase 1)
- Docker 컨테이너 기반 on-premise 에이전트.
- PACS 연동: DICOM C-FIND, C-MOVE, C-STORE; DICOMweb WADO-RS, QIDO-RS.
- DICOM 메타데이터 익명화(PHI 제거, UID 재생성, 날짜 시프트).
- 번인 텍스트 OCR 마스킹, 3D defacing(해당 시리즈 한정).
- 중앙 서버와 암호화(TLS 1.3) 통신.
- 로컬 감사 로그 + 무결성 해시(SHA-256).

### 4.2 중앙 메타데이터 인덱스 (Phase 1)
- 수집된 메타데이터 통합 인덱스.
- 코호트 검색 API: modality, body part, 연령대, 성별, 진단명(ICD-10/RadLex), 장비 제조사, 촬영 연도 범위.
- NLP 라벨 엔진: 판독문에서 진단명·소견 자동 추출(LLM 기반).
- 병원별 데이터 현황 대시보드.

### 4.3 구매자 포털 (Phase 2)
- 코호트 검색 UI, 필터링, 썸네일 미리보기.
- DICOM 웹 뷰어 통합(Cornerstone.js/OHIF).
- 장바구니, 견적 생성, 결제(Stripe).
- 다운로드 매니저(S3 presigned URL, 7일 TTL).
- Developer API + Python SDK.

### 4.4 주문 처리 (Phase 2)
- 구매 확정 → Gateway로 전송 명령 → De-ID 재검증 → 클라우드 임시영역 적재 → 구매자 다운로드 → TTL 만료 자동 삭제.
- 이벤트 드리븐(SQS/SNS/Lambda).
- 진행 상황 실시간 추적.

### 4.5 라벨링 파이프라인 (Phase 2)
- Tier 1 자동(NLP) / Tier 2 전문의 / Tier 3 세그멘테이션.
- 라벨러 전용 워크벤치 또는 외부 도구 연동(V7/Encord/Label Studio).
- Inter-annotator agreement(Cohen's κ, Dice) 산출·공개.

### 4.6 빌링 & 수익 분배 (Phase 2)
- Tier별 단가 책정, 볼륨 할인.
- 병원별 수익 자동 정산(월 단위), 투명 대시보드.
- 세금계산서/인보이스 자동 발행.

### 4.7 감사 & 컴플라이언스 (전 Phase 상시)
- 모든 데이터 접근·전송 감사 로그 불변 저장.
- 병원별 데이터 철회권(30–90일 내 삭제).
- SOC 2 Type II + ISO 27001 준비(Phase 2–3).

## 5. 비기능 요구사항

- **보안**: 전송 TLS 1.3, 저장 AES-256, MFA 필수, 역할 기반 접근 제어(RBAC).
- **가용성**: 중앙 서비스 99.9% SLA (Phase 2+).
- **성능**: 코호트 검색 응답 <2초(p95), 주문 후 다운로드 가능까지 <48시간.
- **확장성**: 병원 100곳, 총 1억+ 스터디 메타데이터 처리.
- **국제화**: UI 한국어/영어, 구매자는 영어 우선.
- **감사 적합성**: 개인정보보호법, HIPAA, SOC 2 Type II, ISO 27001.

## 6. Non-goals (명시적으로 하지 않을 것)

- **환자 직접 데이터 업로드** (C2B2B) — 규제/품질 리스크로 폐기.
- **자체 AI 모델 개발·판매** — 데이터 플랫폼에 집중, 수직 통합 안 함.
- **실시간 임상 의사결정 지원** — 판매 후 구매자 용도, 플랫폼은 제공자 역할만.
- **환자 식별 가능한 데이터 전송** — 완전 익명정보 이외 불가.
- **병원 PACS 교체·수정** — 표준 프로토콜로 외부 연동만.

## 7. 성공 지표 (KPI)

### Phase 1 (0–6개월)
- 병원 파일럿 2곳 계약 체결.
- Gateway Agent 1곳 이상 실제 배포·가동.
- 메타데이터 최소 10,000 스터디 인덱싱.
- 법률 자문 완료 + 표준 병원 계약서 v1.

### Phase 2 (6–18개월)
- 병원 10곳+ 운영, 스터디 100만+.
- 유료 구매자 5곳+, 연매출 $450K+.
- SOC 2 Type I 취득.

### Phase 3 (18–36개월)
- 병원 30곳+, 스터디 500만+.
- 연매출 $1.5M+, Gross margin 60%+.
- SOC 2 Type II + ISO 27001 취득.
- 시리즈 A 유치.

## 8. 제약

### 법적
- 한국 개인정보보호법 제28조의8: **완전 익명정보만 국외이전 가능**.
- 의료법·생명윤리법 중첩 해석: 법률 자문 필수.
- HIPAA de-identification 기준 충족.

### 기술
- PACS 벤더 비의존: DICOM 표준 프로토콜만 사용.
- 판독문은 RIS/EMR에 별도 저장되는 경우 많음 → Phase 1은 메타데이터만, 판독문 연동은 Phase 2.
- 희귀질환·소아 영상은 재식별 리스크로 초기 제외.

### 비즈니스
- 병원 Revenue share 25–50% (Tier별 차등).
- 최소보장금(MG): Phase 1 파일럿 병원에 한해 연 ₩500–1,000만 제공.
- 초기 자본 제한: 2인 팀 + 클라우드 최소 구성으로 Phase 1 완주.

## 10. 리스크 및 가정

- **가정 1**: 한국 병원이 합리적 경제 조건 + 법적 안전성 확보 시 공급 파트너로 참여할 의사가 있다.
- **가정 2**: 글로벌 AI 기업이 한국 데이터에 프리미엄을 지불할 의사가 있다(리서치 §4 근거).
- **가정 3**: 현행 개인정보보호법의 "익명정보 제외" 조항이 플랫폼 운영 기간 중 유지된다.
- **리스크 상세**: [리서치 §12](research/k-meddata-research-summary.md#12-핵심-리스크) 참조.
